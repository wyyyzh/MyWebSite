## 零、改内容的固定循环（先看这段）

记住这个循环，以后改任何东西都是这四步：

```
1. 改文件    →  只动 src/data/ 下的 .ts，或根目录 index.html
2. 保存      →  Ctrl + S
3. 看浏览器  →  如果 npm run dev 开着，页面自动刷新，不用重启、不用刷新
4. 推上线    →  git add -A && git commit -m "更新内容" && git push
```

第 3 步是「热更新」。前提是你开着 `npm run dev` 那个黑色窗口 —— 关了就没有，那就得重新跑一次。

第 4 步才会影响到已经发布的网站。**本地改了但没 push，线上是不会变的。**

### 文件格式的三条铁律

`.ts` 文件比你想象的严格，破一条就白屏：

| 铁律 | 对的写法 | 错的写法 |
| --- | --- | --- |
| 文字必须用引号包住 | `title: '我的项目'` | `title: 我的项目` |
| 每个字段结尾要有逗号 | `year: '2026',` | `year: '2026'` |
| 文字里有单引号要转义 | `'这是\'我的\''` | `'这是'我的''` |

**最常见的崩溃场景**：最后一条。你在自我介绍里写了英文的所有格（比如 `I'm`），那个撇号会把字符串提前截断，整站白屏。中文的引号「」和 "" 完全没问题，随便用。

**学会了就够用**：想知道错在哪，看终端里那行红色的报错，它会告诉你 `src/data/xxx.ts:12:30` —— 12 行 30 列，精确到字符。

### 改坏了怎么回滚

```bash
git diff src/data/site.ts     # 看看改了什么
git checkout -- src/data/site.ts   # 不要这次改动，恢复到上次提交的样子
```

放心改，有 git 兜底，删不掉东西。

## 一、`src/data/site.ts` —— 你是谁

| 字段 | 说明 | 参考写法 |
| --- | --- | --- |
| `name` | 真实姓名 | `张小明` |
| `handle` | 页面上称呼你，可以只写名或英文名 | `小明` / `Ming` |
| `version` | 当前人生版本号，随便定，会显示在右上角 | `v2.1.0` |
| `versionName` | 这个版本的一句话概括 | `在大厂做增长 · 筹备副业` |
| `tagline` | Hero 大字，一句话让人记住你。用 `\n` 断行 | ``不是名校生。\n是一个一直没停下的人。` |
| `subtitle` | 副标语，一两句补充 | `记录我做的每一个小东西。` |
| `role` | 职业身份，会自动转大写显示 | `前端工程师 / 摄影爱好者` |
| `intro` | 自我介绍，数组，每个元素一段（建议 2-3 段） | 见下方模板 |
| `exploring` | 你现在最想搞明白的问题 | `AI 会让「会写代码」变得多廉价？` |
| `email` | 联系邮箱 | `hi@yourdomain.com` |
| `links` | 社交链接，`external: true` 表示新窗口打开 | `{ label: 'GitHub', href: 'https://github.com/xx', external: true }` |
| `readme` | 点右上角 `/README.md` 弹出的内容 | 见下方模板 |

**intro 段落模板**（照这个结构写最容易读）：

```
1. 我是谁 + 目前在做的事        → 一句定位
2. 我做过什么、擅长什么          → 两三件具体的事，别写形容词
3. 我在找什么 / 下一步想做什么    → 给对方一个联系你的理由
```

**readme 模板**：

```ts
readme: [
  '# README.md',
  '',
  '## 我是谁',
  '一句话说清。',
  '',
  '## 我擅长什么',
  '- 具体能力一',
  '- 具体能力二',
  '',
  '## 我在找什么',
  '一段话。',
  '',
  '## 怎么联系我',
  '发邮件最快，一般一天内回。',
]
```

## 二、`src/data/projects.ts` —— 你做过什么

每个项目填 5 个字段，建议准备 **4-8 个**：

| 字段 | 说明 | 注意 |
| --- | --- | --- |
| `title` | 项目名 | 带上你给它起的花名更容易记 |
| `summary` | 一两句说清这是什么、解决谁的什么问题 | 别写技术栈，写价值 |
| `highlights` | 最多 3 条要点 | 优先写**结果和数字**，不写"参与了""负责了" |
| `tags` | 3 个标签 | 用名词：`产品` `硬件` `数据分析` |
| `year` | 年份 | 字符串 |
| `visibility` | `公开` / `私密` / `进行中` | 影响卡片右上角标签颜色 |
| `featured` | 首页是否直接展示 | 精选 4 个设为 `true` |

> 写要点的小技巧：把「负责了用户调研」改成「访谈 23 个用户，砍掉了 60% 的功能清单」，立刻有说服力。

## 三、`src/data/timeline.ts` —— 你的转折点

写 **4-7 条**，每条是一次「发布」。按时间**倒序**排（最新的在最前面）。

| 字段 | 说明 |
| --- | --- |
| `version` | 版本号，按倒序递减：`v1.0.0` → `v0.9.0` → `v0.8.0` |
| `date` | `2026.09` 这种格式 |
| `title` | 一句话概括这个阶段 |
| `description` | 一两句说清发生了什么、你学到了什么 |
| `type` | `major` 人生转折 / `minor` 新项目 / `patch` 小修补 |

**筛选标准**：只留「改变了你后续走向」的事。实习、转岗、退学、搬家、第一次做成某件事——都算。

## 四、`src/data/activity.ts` —— 你的活跃轨迹

先用示例数据没关系。想换成真实的，按这个来：

1. 找到 `USE_MANUAL_DATA`，改成 `true`
2. 在 `manualData` 里填 `'2026-01-04': 3` 这样的键值对
3. 数值范围 0-8（0 = 那天没记录），会映射到 5 档颜色

数据从哪来：
- **写博客/笔记**：按发布数量填
- **敲代码**：用 GitHub 贡献数
- **健身/读书**：按当天的时长或页数折算成 1-4

定义完全由你决定，只要全站统一。图例里已经写好「少 → 多」。
